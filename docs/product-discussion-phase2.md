## 1. 阶段定位

> Phase 2 的目标，是让 Echo 从安静的收集与搜索工具，逐步成为多 LLM
> 思考场景下的个人反思层。机器负责连接，人负责判断。

这不是自动推送层，也不是第二大脑。默认不打扰，不要求用户维护内容，
只有用户正在关注某段文字、并且已经打开 Echo 时，系统才可以温和地提示
存在相关旧 Echo。

## 2. 为什么进入 Phase 2

竞品分析得出的方向判断：

- 跨模型存储、语义搜索和上下文注入正在商品化。
- Recall、Constella 已接近相关内容浮现，但仍以知识库和研究资产为中心。
- Echo 的机会不是记住更多，而是只保存用户明确点亮的内容，并在需要时
  让过去的自己回来。
- 差异化不在存储容量，而在浮现质量、解释能力和打扰成本。

风险同样明确：

- 错误的浮现比错误的搜索更冒犯。
- 打开侧边栏就展示一组推荐，会重新制造 Top 3 实验中的作业感。
- 尚未验证交互价值前，不应先建设向量、反馈训练和复杂排序基础设施。

## 3. Reflection Probe v0

### 3.1 只验证一个问题

> 当用户选中文字、且 Echo 已经打开时，如果只出现一行
> 「找到 N 条相关 Echo」，用户会愿意主动点开吗？

这是一个允许在数天 dogfood 后被否定的实验，不是完整 Reflection Layer。

### 3.2 最小流程

```text
用户在支持的 LLM 页面选择文字
  → 已打开的 Sidebar 收到选区
  → 本地计算旧 Echo 的关键词相关性
  → 有过线结果：相关 Echo **置顶进 Home 列表**（高度相关淡蓝底）
  → 无需点击展开；Probe debug 仍可用于算法调试
```

## 4. 交互契约

- 不自动打开 Sidebar。
- 不弹窗，不抢焦点，不播放声音。
- 没有高置信结果时保持沉默。
- 新选区出现时，旧相关置顶状态随选区更新。
- 相关结果只是入口，不形成待处理队列。
- 忽略不等于删除，也不要求用户反馈。

### v0.2 调整（2026-07-03 dogfood）

- **放弃**「一行折叠 + 必须点开」：测试阶段多点一次就嫌烦。
- **改为**相关 Echo 直接置顶进列表；**高度相关**给淡蓝背景。
- 仍不自动打开 Sidebar、不在页面内浮层提示。

## 5. 相关性规则

当前 A 版只使用本地、确定性、可解释的词法规则：

- 查询只来自用户当前明确选择的文字，不读取整页作为主题。
- 使用 `Intl.Segmenter` 处理中文与英文词，不再暴力切全部二元片段。
- 查询词必须真实出现在现有 Echo 语料中，并按 IDF 只保留最多 16 个。
- 使用 BM25 处理词频饱和与字段长度，避免长选区、长正文天然高分。
- `userThought` 仅有小幅加权；每条 Echo 只取最佳字段，不跨字段重复累计。
- 连续 token 在同一字段出现时获得短语奖励。
- 分数归一化为 0–100：强相关与可能相关都保持折叠，弱相关不展示。
- 只有原文与 URL 都相同才视为自我召回。
- 每条结果只解释真实词法证据，不冒充语义理解。

当前不使用 AI、Embedding、向量数据库、模糊黑盒排序或云端请求。

## 6. 成功与停止标准

### 6.1 观察信号

- **触发率**：有效选区中有多少次出现过线结果。
- **展开率**：提示出现后，用户是否主动查看。
- **使用率**：展开后是否复制、Pin 或打开原位置。
- **打扰感**：是否出现「它又来烦我」的主观反馈。

### 6.2 决策规则

- 愿意展开且结果有用：继续优化相关性。
- 愿意展开但结果不准：调整规则，再考虑语义能力。
- 基本不展开：交互假设不成立，停止扩建。
- 即使折叠仍感到打扰：退回纯 Search，不为差异化强留功能。

- `sourceApp`

## 8. 明确暂缓

- 页面全文级自动相关。
- 自动展开或页面内主动提示。
- 每日浮现次数、冷落驱动和定时推送。
- AI 语义检索、Embedding 和向量数据库。
- 对比视图、主题聚类和知识图谱。
- 「有用 / 不相关 / 暂时隐藏」反馈训练系统。
- 新的数据状态、任务箱或维护流程。

## 9. 开发记录

### 2026-07-03：范围建立

- 将几个月的 Reflection Layer 建设拆为可在约 1–2 周内验证的 Probe。
- 确认 Phase 2 数据基础已经存在。
- 选择「明确选区 + Sidebar 已打开 + 单行折叠提示」作为第一实验。
- 保留随时停止并退回纯 Search 的权利。

### 2026-07-03：Reflection Probe v0 实施

已完成第一版代码：

- 支持的 LLM 页面在选区变化后发送临时文本上下文。
- Sidebar 未打开时没有后续动作；选区不会写入 Dexie。
- 新增本地相关性纯函数：英文单词、中文二元片段、字段权重、短语加分和
  最低门槛。
- 单个弱关联词不会触发提示。
- 与选区原文完全相同的 Echo 被排除，避免自我召回。
- 有过线结果时只显示「找到 N 条相关 Echo」，默认折叠。
- 主动展开后最多显示 3 条，附带字段和命中词解释。
- 复用现有 Copy、Pin、Delete、打开原位置和补想法动作。

工程验证：

- TypeScript 检查通过。
- 3 个测试文件、20 个测试通过。
- 没有新增 Dexie schema、索引、状态或网络请求。

### 2026-07-03：加入 Probe 调试状态

实际收藏数较少时，第一版一次也没有触发。当前无法从 UI 判断是：

- 页面选区没有传到 Sidebar。
- 选区被切成了不足两个 token。
- 候选有重合但低于固定门槛。
- 候选被「原文完全相同」规则排除。
- 确实没有任何词法重合。

因此先加入默认折叠的 `Probe debug`：

- 未收到选区时显示「等待页面选区」。
- 收到后显示选区、token、扫描条数和过线条数。
- 展开后列出分数最高的 5 个候选。
- 每个候选显示原始分、命中词和明确拒绝原因。

调试状态是实验仪器，不是正式产品功能。相关性算法在这一步保持不变，
避免同时修改测量工具和被测对象。

### 当前算法已确认的结构性问题

1. **固定门槛没有归一化**：长选区天然产生更多 token 和更高分，短选区即使
   很明确也可能永远过不了线。
2. **跨字段重复累计**：同一个词同时出现在标题和正文会重复加分，不等于
   语义更相关。
3. **中文二元片段噪音大**：常见组合会制造假关联，近义表达又完全无法命中。
4. **没有语料稀有度**：所有 token 等价，「产品」和一个极少出现的专有概念
   得分相同。
5. **高价值字段仍被统一门槛压制**：`userThought` 中一个非常明确的命中也会
   因总分不足被拒绝。
6. **完全相同原文排除过粗**：没有结合 URL 判断，另一场对话中再次出现相同
   观点也会被错误排除。

这些问题已由 A 版词法基线处理。Embedding 仍暂缓，先观察 BM25 在真实
dogfood 中能达到的上限。

### 2026-07-03：A 版词法基线

真实调试样本中，274 个 token 的长选区让旧算法用「实用、这个、快速」召回了
三条无关 Echo。这证明旧算法不是门槛太高，而是评分对象错误。

已替换为：

```text
Intl.Segmenter
  → 停用词过滤
  → 只保留语料中存在的词
  → IDF 选择最多 16 个高信息词
  → 分字段 BM25 + 长度归一化
  → 连续短语奖励
  → 只取最佳字段
  → 0–100 置信度
```

本轮明确没有加入：

- 手工同义词扩张。
- Embedding 或 Transformers.js。
- 强相关自动展开。
- 跨字段重复加分。

新增真实误报回归：长选区中包含 `checklist / native English speaker`
时，具体英文检查 Echo 可以通过；只包含「实用、这个、快速」的泛化卡片不能通过。

验证：TypeScript 通过；4 个测试文件、27 个测试通过。

### 2026-07-03：逐条 Echo 评分账单

为避免“高度相关”再次成为无法核查的结论，`Probe debug` 改为显示所有被扫描
Echo，而不是只显示前 5 条。

每条 Echo 可以展开看到：

- 最佳匹配字段及字段权重。
- 当前字段 token 长度与语料平均长度。
- 每个命中词的 TF、IDF 和 BM25 分数贡献。
- 连续短语奖励。
- 加权前后的原始分与 0–100 置信度。
- 最终通过或拒绝原因。

没有任何重合的 Echo 也会记录参与评分的查询词、BM25 为 0 和无短语命中。
这个账单只用于 Probe 期间调试，算法稳定后应移除或隐藏在开发设置中。

### 2026-07-04：一键复制 Probe 报告

手工填写 Case 表不符合 Echo 保护用户懒惰的原则，也很难长期坚持。

调试面板新增「复制报告」：

- 自动带上当前选区和真正参与评分的语料词。
- 自动带上扫描数、过线数和全部候选。
- 每条候选包含 ID、通过/拒绝、置信度、原因和完整 BM25 账单。
- 输出为 Markdown，可直接贴回开发对话讨论。

复制完全由用户主动触发；系统不自动保存选区、行为日志或调试报告，也不上传网络。
Case 表继续保留为结论摘要，不再要求手工录入每次实验。

### 2026-07-04：精简多报告格式

连续粘贴两份完整报告后，零分 Echo 占据大部分篇幅，报告边界也不明显。

复制格式调整为：

- `confidence = 0` 的 Echo 不逐条输出，只在 Summary 汇总数量。
- 仅输出有实际证据的候选，并保持置信度排序。
- 每份报告包含时间 ID 和明确的 START / END 标记。
- 固定 Summary 表展示扫描数、有证据数、过线数和零证据数。
- Echo 标题压成单行，避免收藏段落破坏 Markdown 结构。

Sidebar 内的完整 debug 账单仍保留；精简只影响复制结果。

### 2026-07-06：16 份 Probe 报告审计与 precision-first 收紧

对 16 份真实报告重新结构化统计：

| 指标 | 结果 |
| --- | ---: |
| 总候选扫描 | 1,493 |
| Accepted | 256 |
| 平均每次 Accepted | 16 |
| 最大 Accepted | 30 |
| 仅靠一个词过线 | 139（54%） |
| 无连续短语 | 250（97.7%） |
| 最佳字段为 `triggerText` | 252（98.4%） |
| 单词 + 无短语但分数 ≥60 | 76 |

结论：旧规则不是偶尔误报，而是把 BM25 的稀有词和短文档奖励错误解释成了
思想相关性。「置信度」也只是 BM25 的映射值，不是经过标注校准的概率。

新的浮现资格：

```text
一个词
  → 永不浮现

两个有效内容词
  → possible-only，只留在 debug

连续有效短语
  或同一字段 ≥3 个有效内容词
  → 才允许进入列表
```

辅助约束：

- Tier 2 泛词只乘 `0.35`，可以影响排序但没有浮现投票权。
- 语料至少 10 条后，文档频率超过 20% 的词自动降为 Tier 2。
- 短 Echo 的计分长度最低按同字段平均长度的一半计算，限制短文档奖励。
- 重复内容只保留最高排名的一条，其余在 debug 标记 `duplicate`。
- UI 数字改称「词法证据」，不再暗示它是真实概率。

这是对 BM25 的最后一轮高精度定位：它负责提供明确共词候选，不负责理解
同义、认知状态或决策关系。Embedding 继续暂缓，等待收紧后的真实漏报证据。

### 2026-07-03：中文停用词与 query 侧过滤

## 10. 中文词「有用程度」（探索中）

停用词解决的是 **绝对无意义**（`什么`、`是在`）。  
Dogfood 表明还有第二层：**不是停用，但信息量低**——IDF 认为「够稀有」，
人眼却觉得不该撑起「高度相关」。

典型误报词（待验证）：`下来`、`继续`、`明显`、`变成`、`接近`、`发现`、
`推荐`、`优先` 等。

典型有用词（待验证）：专有名词 / 英文术语（`gemini`、`idf`、`bm25`）、
3–4 字名词短语（`时间锚点`、`按结果收费`）、`userThought` 里的概念词。

### 10.1 当前系统用什么、缺什么

| 信号 | 作用 | 局限 |
|------|------|------|
| IDF | 语料越少见 → 分越高 | 小语料里泛化词 idf 仍不低 |
| 停用表 | 硬删无意义词 | 只能逐个补，边界模糊 |
| `STOP_QUERY_CJK` | 仅选区侧过滤 | 已用于 `还给` 等边界词 |
| 字段权重 | userThought 略高 | 字段内所有词仍一视同仁 |
| 短语奖励 | 连续词命中加分 | 依赖 Segmenter 切分质量 |

**缺口**：没有「有用程度」分档——泛化二字词与真概念词在 BM25 里得分接近。

### 10.2 假设分档（规律尚未证实，勿急于编码）

```text
Tier 0  绝对无意义     → 全局停用（什么、是在、的是）
Tier 1  偶有实义、常噪音 → 仅 query 停用（还给）
Tier 2  泛化动词/副词   → 降权，不删除（继续、下来、明显、变成、接近…）
Tier 3  普通内容词     → 保持 IDF + BM25（定价、记录、召回、训练…）
Tier 4  高价值信号     → 加分（英文/专有名词、3+ 字短语、userThought 概念词）
```

**暂存假设（待 case 验证）：**

1. 多个 Tier 2 重合 **不应 alone 撑起「高度相关」**。
2. 强相关应至少含一个 Tier 4，或 ≥2 个 Tier 3，或有 ≥3 字连续短语。
3. 语料出现率 >20% 的二字词 → 降权或不得单独过线（文档频率上限）。
4. **降权优于停用**：`继续` 在「继续迭代定价」里仍有意义，不宜硬删。

Embedding 仍暂缓。先靠分档 + 降权 + 门槛收紧摸词法上限。

### 10.3 下一步算法方向（有 case 后再动代码）

优先级：

1. Tier 2 降权系数（如 ×0.3–0.5），不扩停用表。
2. 强相关门槛：禁止「纯 Tier 2 组合」过线。
3. 文档频率上限（跨 Echo 太常见的二字词）。
4. 3–4 字短语优先于散碎二字词。

## 11. Case 记录（随缘积攒）

> **说明**：下面这张表理论上很有用，实际上很难坚持填——  
> 遇到离谱误报/惊喜命中时随手记一笔即可，不追求完整。  
> 5 条真实 case 比 50 行空表有用。

### 11.1 极简记录格式（一行一条）

```text
[误报|命中|漏报] 选区前 20 字… → 结果标题前 20 字… | 参与评分词 | 你觉得该算有用的词
```

**示例：**

```text
[误报] 推荐优先级接下来… → 快速对比表 | 下来、继续、明显 | 应：优先级、second brain
[命中] checklist native English… → English copy review | checklist、english、speaker | 同左
```

### 11.2 完整表（有精力再填）

## 12. 烧鸟之夜：Thought Continuity 转向（2026-07-06）

> **背景**：低压社交（烧鸟 + 新朋友）后的安全感恢复，认知空间重新打开；从
> 「今天很开心」自然滑入「独立开发有没有得做 / 红海 / Recall 怎么办」——这是
> **情绪恢复 → 身份与方向确认** 的状态切换，不是随机发散。

### 12.1 一晚压缩成三句

| # | 层面 | 结论 |
| --- | --- | --- |
| 1 | **产品定义** | Not memory. **Thought continuity.** |
| 2 | **技术姿态** | 不做 taxonomy，做 **description + observation + emergent pattern** |
| 3 | **研究问题** | 人在 LLM 协作下，思考如何 **重复、演化、断裂**？能否被 **观测** 而非 **定义**？ |

更激进的一句：

> **帮助过去的自己参与今天的思考** —— reactivation，不是 retrieval。

### 12.2 概念跃迁链（按顺序）

```text
触发：低压状态 → 敢想本质问题
  ↓
冲突：「是不是 Recall 红海？」→ 表层错问是「有人做了吗」
  ↓
改写：「我是不是只是 Recall-lite？」→ 若问题不同则非竞争
  ↓
定义：Memory（存信息 / keyword similarity）
      → Thought Continuity（连思考 / cognitive state / reactivation）
  ↓
推翻：中文语义优化不是核心 → 核心变量是 State / Decision / Trajectory
  ↓
案例：「又开始怀疑方向」应浮现 **同一认知循环**，而非含「产品方向」的旧文
  ↓
刹车：❌ 人工 Cognitive Taxonomy（会固化、限制数据）
      ✅ LLM **描述**当前片段（动态、生成式，不贴静态标签）
  ↓
管线：Collect → LLM 描述 → 存 Thought → 用户行为反馈 → 隐式学习 → pattern 涌现
  ↓
指标：Embedding similarity ❌  ·  Cognitive usefulness ✅（是否真帮用户继续想）
  ↓
身份：从「设计产品」→「观察人类思考结构」→ 产品从数据里长出来
```

### 12.3 与 Recall / 红海论的对齐

文档 `technical-moat-analysis-2026-07.md` 与当晚结论一致：

- Recall 强在 **知识库 + 图谱 + 复习闭环**；Echo 强在 **高意图瞬间 + 打扰成本 + 可解释浮现**。
- 若 Echo 只是 Recall-lite → 无意义；若解决 **「思考状态接续」** → 不同问题、不同品类。
- 护城河不在「更大的库」，而在 **何时浮现、何时沉默、为何如此** 的个人化排序（需行为信号累积）。

### 12.4 与当前 Phase 2 的关系

| 我们在做的 | 今晚推导的 | 关系 |
| --- | --- | --- |
| BM25 / 词法 Probe | 「语义不是核心」 | **一致**：词法只做共词候选门，不冒充 state matching |
| precision-first 收紧（2026-07-06） | 减少假相关 = 保护「认知有用性」前提 | **必要**：错的浮现比空的浮现更伤 |
| Embedding / 向量 | 暂缓 | **仍暂缓**；没有 usefulness 反馈前，向量只是另一种误报引擎 |
| Case 2–4（决策/情绪/模式相同、无共词） | Thought Continuity 的真正价值 | **当前 Phase 2 刻意不碰**；这是 2.5/3 的研究议程 |

**定位修正**：

```text
Phase 2     = 词法门控 + dogfood（敢浮现 / 敢沉默）
Phase 2.5   = 观测基础设施（描述、行为信号、不定义 taxonomy）
Phase 3     = reactivation 排序（cognitive usefulness > similarity）
```

### 12.5 可行性分析

#### ✅ 现在就能做、且与愿景同向

| 项 | 可行性 | 说明 |
| --- | --- | --- |
| **产品叙事** | 高 | Thought Continuity 作对外/对内北极星；BM25 明确降级为「临时门控」 |
| **Collect 不动** | 高 | 已有 trigger / userThought / anchor / sourceApp；符合「只存点亮瞬间」 |
| **Probe 当观测仪器** | 高 | 复制报告、词法证据、possible-only 留 debug = 观察而非宣称智能 |
| **隐式行为信号（本地）** | 中高 | Pin、Copy、Open source、展开相关卡片、忽略（无操作）——可先只记本地计数，不训练 |
| **LLM 描述（可选、按需）** | 中 | 用户 Keep 或 Pin 时异步生成 **一段自然语言描述**（非分类）；需额外 API、隐私与成本决策 |
| **precision-first 词法** | 高 | 已 ship；继续 dogfood 看空列表率与漏报 |

#### ⚠️ 能做但容易做错（需约束）

| 项 | 风险 | 建议 |
| --- | --- | --- |
| **保存时自动打标签** | 重蹈 taxonomy 覆辙 | 只允许 **paragraph 描述**；禁止固定 enum / 固定维度打分 |
| **Embedding 召回** | 回到 Probe Report 式泛语义噪 | 等 usefulness 信号 + 描述文本就绪后再开；且仅作候选生成，不作最终排序 |
| **「认知状态」硬编码** | Product Doubt / Imposter 等标签 | 用 LLM 描述 + 事后聚类观察；标签只能出现在分析笔记里，不进 schema |
| **手太紧的空列表** | 用户以为坏了 | 维持 debug 可见；若空列表 >70% 再松 `userThought` 两词例外 |

#### ❌ 短期不可行（诚实边界）

| 项 | 原因 |
| --- | --- |
| **Case 2：无共词决策相似** | 需 state 描述 + 向量或结构化相似 + 反馈；词法无解 |
| **Case 3：情绪状态相似** | 同上；且情绪标注极易肤浅 |
| **Case 4：思维模式 / 错误模式** | 需 longitudinal pattern；语料与信号量远不够 |
| **「从数据长出产品」全自动** | 需要大量 dogfood 时长 + 可复现的 usefulness 定义 |
| **靠 Phase 2 BM25 验证 Thought Continuity** | 指标不对；应用「是否帮我想下去」主观标准，不用过线条数 |

### 12.6 建议的最小路径（不推翻 Phase 2）

**接下来 2–4 周仍留在 Phase 2**，但心里装着 2.5：

1. **Dogfood precision-first 词法** — 指标：空列表率、debug 里「该出不出」条数，而非 accepted 数。
2. **行为信号草稿（仅本地）** — 对每次浮现记录：`shown / copied / opened / pinned / ignored`（忽略 = 无操作超时）；不上传、不训练，先能查。
3. **一篇描述实验（可选分支）** — Keep 时对 `userThought || triggerText` 调一次 LLM 生成 **3 句以内观测描述**，存入 `capture` 新字段或 `inferredThought` 扩展；**不展示分类 UI**。
4. **Case 表只记 Continuity 型** — 专门记「无共词但应该相连」的漏报，为 Phase 3 攒需求，不逼 BM25 解决。

**明确不做（今晚已刹车）**：

- Cognitive Taxonomy schema
- 为追 Recall 而扩成知识库 / 图谱
- 用 Embedding 替换词法门控（在 usefulness 闭环之前）

### 12.7 一句话裁决

> **Thought Continuity 作为方向：高度可行，且与 Echo 已有 Collect 哲学一致。**  
> **作为 Phase 2 实现手段：不可行——BM25 只是门卫；真正难点是 observation + usefulness，属于 2.5/3。**  
> **今晚的价值是停止用错误指标（语义/过线数）证明错误问题（memory vs continuity）。**

### 12.8 待验证假设（写入 case 表即可）

```text
[H1] 低压/高压后用户划词主题会系统性不同（状态影响 Collect 内容）
[H2] userThought 的浮现比 triggerText 更值得信任（需行为信号验证）
[H3] 一段 LLM 描述比多 10 个停用词更能减少「像但不帮想」的误报
[H4] 无共词决策相似在 <200 条语料下无法自动召回，只能手动 Pin 训练样本
```

## 13. Phase 2.1：收藏意图与选区语境分层

**建立日期**：2026-07-08  
**阶段目标**：让 Probe 报告能解释「这次选区在找什么、候选 Echo 是什么、
这次命中到底是哪种召回」，避免把测试收藏、任务材料和自然洞察混在一起评估。

### 13.1 新 dogfood 洞察

Echo 不一定一直被打开，但用户即使不打开也会继续划词收集。打开 Echo 的动机
很多时候不是管理知识库，而是查看最近收集、复制精简报告、观察 Probe 表现。

因此：

```text
Collect 是主流程
Sidebar 是工作台
Probe 是用户主动打开时的分析层
```

用户不打开 Echo，不代表 Echo 没有在被使用。只要用户仍在划词收藏，Echo 就在
发挥价值。

### 13.2 为什么不能只给 Echo 分桶

相关性不是 Echo 的单体属性，而是：

```text
selection kind × echo intent → match kind
```

如果只判断候选 Echo 是什么，仍无法解释以下情况：

| 选区 | 候选 Echo | 解释 |
| --- | --- | --- |
| product-thought | insight | Thought Continuity，最接近 Phase 2 目标 |
| product-thought | product-meta | 产品资料/观点参考，有用但不是最终 continuity |
| product-thought | task-material | 任务材料召回，技术上可接受但语义不是 continuity |
| product-thought | debug | 疑似 Debug Noise，应优先查规则 |
| task-material | task-material | BM25 最擅长的同任务材料召回 |
| meta-debug | debug/product-meta | 可用于 dogfood 分析，但不应证明产品价值 |

### 13.3 当前内部分类

```ts
type SelectionKind =
  | "product-thought"
  | "task-material"
  | "meta-debug"
  | "unknown"

type EchoIntent =
  | "insight"
  | "product-meta"
  | "task-material"
  | "debug"
  | "unknown"

type RecallMatchKind =
  | "thought-continuity"
  | "product-meta-reference"
  | "task-material-recall"
  | "debug-noise"
  | "weak-lexical-overlap"
  | "unknown"
```

这些分类不展示为用户需要维护的标签，也不写入 Dexie schema。它们暂时只服务
Probe 报告与算法分析。

### 13.4 朴素规则（可被狗粮推翻）

选区：

- `product-thought`：含红海、Recall、Continuity、方向、怀疑、差异化、浮现、唤回等。
- `task-material`：含 Procreate、Tailwind、导出、步骤、画布、配置、素材、指南等。
- `meta-debug`：含 Phase、Probe、BM25、case、schema、dogfood、报告、调试等。

Echo：

- `insight`：第一人称判断、顿悟、感悟、真正值得、根本区别等。
- `product-meta`：Recall 对比、系统提示、产品北极星、case 文档、竞品/定位材料等。
- `task-material`：How-to、教程、步骤、设定、导出、实现材料等。
- `debug`：LLM 页标题误存、教练收尾模板、超短无信息条目、Echo dogfood / Probe 记录等。

### 13.5 当前工程边界

本轮只做报告解释，不先改真实列表排序：

- Probe Report 增加 `Selection kind`。
- 每条候选增加 `Echo intent` 与 `Match kind`。
- BM25 的 accepted / rejected 规则保持不变。
- 不清库，不删除测试收藏，不要求用户手动打标签。
- 暂不引入 embedding。先把语料质量与评估口径看清楚。

下一轮再决定是否让 `debug` 硬降权或禁止进入正常列表。倾向规则：

```text
debug 默认只进 Probe debug
除非 selectionKind = meta-debug
且有连续短语
且 >= 3 个 eligible terms
```

### 13.6 判断口径

之后评估 Probe 时，不再只看 accepted 数量：

- `thought-continuity`：真正该重点观察的 Phase 2 信号。
- `task-material-recall`：说明同任务资料找回成立，是基础价值但不是终局。
- `product-meta-reference`：有帮助，但要避免产品文档自己吸住全部 product 选区。
- `debug-noise`：优先修规则或降权。
- 空列表：不一定失败，尤其在没有共词的 continuity 场景中很可能是诚实沉默。
