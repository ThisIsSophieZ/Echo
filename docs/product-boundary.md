## 2. 今天最重要的产品反馈（来自你自己）

> **「确实懒得打开本地 app。」**

这句话否决了原方案「App 内 Review Queue」作为日常路径。

逼出的**设计铁律**：

> **浮现必须长在你已经在的地方，不能要你专门跑过去；也不该要你为了用浮现而启动任何东西。**

## 5. 还没定：架构（下次再聊）

两个方向，今天**没有拍板**：

### 路 A（倾向）：侧边栏就是主界面

- 数据存扩展自带 `chrome.storage`
- **日常不用启动 FastAPI**
- 没有「两个界面同步同一个 Queue」的问题——只有一个界面、一个存储
- 本地 app（FastAPI + prototype）降级为：偶尔导出 / 批量整理

### 路 B：保留本地 app + 侧边栏共享后端

- 唯一数据源 = FastAPI + SQLite
- 侧边栏和 prototype 都读/写同一后端
- **代价**：用侧边栏时本地服务必须开着 → 和你讨厌的摩擦又回来了

**下次讨论时重点问**：侧边栏里要不要做完整整理，还是只做「今日 3 条 + 快捷动作」？
