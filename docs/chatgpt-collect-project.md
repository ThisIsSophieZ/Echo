# ChatGPT Collect Project

## 项目名称

暂定名：`ChatGPT Collect`

内部定位：

- 不是新的完整产品
- 是 `Solo Founder OS` 的第一个可自用入口实验
- 目标是验证“重要想法有没有第二次出现的机会”

一句话：

> 在 ChatGPT 网页里选中一段有用内容，点 `Collect`，先保存到项目库里；之后由系统和后台 agent 帮忙整理、找回、重新浮现。

## 为什么从这里开始

之前 `Solo Founder OS` 的愿景比较大，包含：

- 长期记忆
- 写作辅助
- 事实核验
- 多模型对比
- agent 后台整理
- 项目级工作台
- `Project Memory` / `Global Consensus` / `Verification Desk`

这些灵感仍然保留，它们不是被删掉，而是被暂时放到更高层愿景里。

现在的问题是：如果继续从“完整 founder OS”出发，下一步很容易变得太大，既难开发，也难判断到底有没有真实价值。

这次需求收敛来自一个更具体的个人痛点：

- 记忆力差
- 前学后忘
- AI 对话里经常出现当时觉得很有用的判断
- 但几天后很难想起来它在哪里
- 传统笔记、收藏夹和知识库都假设用户会整理、搜索、回看
- 真实情况是，用户经常连“自己该去搜索什么”都忘了

所以当前原型不先做完整 OS，而是先做一个反遗忘入口：

> 让 AI 对话里的 useful point 被低摩擦保存，并在之后重新回到用户面前。

## 产品判断

这个方向有点像“AI 时代的印象笔记 Web Clipper”，但核心不同。

相似点：

- 选中内容
- 一键收藏
- 记录来源
- 进入知识库
- 后续可检索

关键差异：

- 印象笔记主要保存资料，`ChatGPT Collect` 保存对话中形成的判断点
- 印象笔记的结束是保存，这里的保存只是开始
- 普通知识库等用户主动搜索，这里要在相关时机主动浮现
- 传统备忘录奖励整理，这里奖励“再次遇见”
- agent 不负责替用户裁决，只负责后台清理碎片、补充结构、提示相关性

内部原则：

> 不要做一个更漂亮的备忘录，要做一个让旧想法回来找用户的工具。

## 目标用户

第一阶段只服务一个真实用户：

- 经常和 ChatGPT / Claude / Codex 对话
- 会在对话中产生很多有价值的判断、句子、产品想法和技术理解
- 记忆力差，容易前学后忘
- 不愿意维护复杂知识库
- 愿意在看到有用内容时做一个极轻动作

第一阶段不需要证明大众市场，只需要证明自己是否会持续使用。

## MVP 目标

MVP 只验证一件事：

> 选中一段 AI 对话里的有用内容并保存，之后能不能帮助用户重新遇见、复用或沉淀它。

成功不是收藏数量多，而是出现这些信号：

- 用户愿意在 ChatGPT 网页里频繁点击 `Collect`
- 几天后仍然能通过项目库找回关键片段
- 至少有几条旧片段被再次用于写作、决策或产品判断
- 用户开始依赖 `Review Queue` 或相关提醒来找回旧想法
- 一些反复有用的片段自然升级为 `Project Memory`

## 第一版范围

### 1. ChatGPT 网页选中收藏

只支持 ChatGPT 网页端。

用户流程：

1. 用户在 ChatGPT 对话中选中一段文字
2. 页面旁边浮出 `Collect` 按钮
3. 用户点击按钮
4. 弹出一个轻量面板
5. 用户选择项目，可选补一句 note
6. 保存到本地库

第一版不支持：

- Claude
- Gemini
- Cursor
- VS Code
- CLI
- 任意网页

这些入口以后可以扩展，但第一版只做 ChatGPT，避免过早分散。

### 2. 保存内容与来源

每条 `CollectedPoint` 至少保存：

| 字段 | 说明 |
| --- | --- |
| `id` | 收藏点 ID |
| `projectId` | 所属项目 |
| `content` | 原始选中文本 |
| `sourceApp` | 第一版固定为 `chatgpt` |
| `sourceUrl` | 当前 ChatGPT 页面 URL |
| `sourceTitle` | 页面标题或对话标题 |
| `selectedAt` | 收藏时间 |
| `note` | 用户可选备注 |
| `status` | `active` / `archived` / `promoted` |
| `viewCount` | 查看次数 |
| `reuseCount` | 再次有用次数 |
| `createdAt` | 入库时间 |
| `updatedAt` | 更新时间 |

第一版优先保存原文，不要求 AI 当场改写。

### 3. 项目库与回看页面

复用现有 `prototype` 的方向，把它作为本地 review 页面：

- 按项目查看收藏点
- 搜索内容
- 查看来源、时间、备注
- 标记 `Useful Again`
- 归档
- 提升到 `Project Memory`

第一版不追求漂亮完整，只追求稳定可用。

### 4. 后台整理 agent

agent 的角色是后台整理员，而不是裁判。

第一版可以先做三件事：

- 自动生成短标题
- 自动给 2-4 个主题标签
- 找出可能相关的旧片段

agent 不做这些事：

- 不自动删除
- 不自动合并
- 不自动提升为正式记忆
- 不替用户判断“这一定重要”

它只提供解释和候选：

> 这条可能和你之前收过的几条内容有关。

### 5. Resurface / Review Queue

第一版的主动找回可以先很简单：

- 每次打开 review 页面时展示 3-5 条值得复看的片段
- 排序参考查看次数、复用次数、时间跨度、是否有备注、是否和近期收藏相似
- 给出一句 `why surfaced`

示例：

- `你之前复用过这条`
- `这条和最近收藏的 2 条内容相似`
- `这条收藏后已经过了 7 天，还没有被处理`
- `这条有备注，但还没有进入 Project Memory`

## 后续阶段

### 阶段 2：相关内容实时提醒

在 ChatGPT 页面内检测当前对话内容，和旧收藏点做相似度匹配。

当相关度足够高时，侧边栏提示：

> 你之前收过一个相关点。

用户可以选择：

- 查看旧片段
- 标记 `Useful Again`
- 忽略
- 加入当前项目记忆

### 阶段 3：扩展到其他工作入口

可能支持：

- Claude 网页
- Gemini 网页
- Codex
- Cursor / VS Code
- CLI
- 普通网页

扩展原则：

- 先证明 ChatGPT 场景成立
- 再扩展到更多入口
- 不要一开始做通用 Web Clipper

### 阶段 4：回到 Solo Founder OS

当 `Collect -> Agent整理 -> Resurface -> Human确认 -> Memory` 这条链路稳定后，再把它并回更大的 `Solo Founder OS`：

- 写作台使用这些记忆
- 验证台复核时效性内容
- `Global Consensus` 接收反复成立的跨项目判断
- agent 扩展为更强的后台 workflow worker

## 非目标

第一版明确不做：

- 完整知识库
- 通用网页剪藏器
- 自动写文章
- 自动决策
- 多 agent 群聊
- 对外商业化包装
- 复杂权限系统
- 云同步
- 移动端

这些都可以以后再想。当前目标是让自己先真实用起来。

## 最小技术方案

建议沿用当前仓库已有基础：

- `FastAPI` 做本地 API
- `SQLite` 做本地存储
- `prototype` 做 review 页面
- 新增浏览器扩展作为 ChatGPT 网页入口

建议新增目录：

- `extension/manifest.json`
- `extension/content.js`
- `extension/styles.css`

第一版扩展只需要：

- 监听网页选中文本
- 显示 `Collect` 浮动按钮
- 调用本地 API 保存内容
- 允许选择项目和填写可选 note

## 当前下一步

为了加快进度，下一步不要继续扩展产品概念，直接做可自用原型：

1. 修好现有本地 API 和 prototype 的持久化断裂
2. 新增 `CollectedPoint` 或复用 `StarredFragment` 支持 `sourceApp` / `sourceUrl`
3. 新增 ChatGPT 网页扩展
4. 打通 `选中文字 -> Collect -> 本地库 -> Review 页面可见`
5. 自己连续使用 1-2 周，记录哪些片段真的被再次使用

如果这条链路自己用不起来，后面的 founder OS、agent、写作台都先不要加。

如果这条链路能用起来，再继续做 `Review Queue` 和后台整理 agent。
