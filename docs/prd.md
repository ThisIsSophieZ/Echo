# PRD

## 产品名称

Solo Founder OS

## 产品一句话

一层给一人公司老板使用的 **Memory Layer（记忆基础设施）**——不是 Agent，也不是 Skill。它低摩擦保住你在 AI 对话里产生的有用判断，并在对的语境把对的旧片段重新还给你。

> 使命：不是帮你存更多，而是降低"旧想法 × 新语境"撞上的成本。

定位详见 `docs/memory-layer-design.md`。

## 背景

目标用户是一个很较真的老板。他会同时使用多个 LLM 产出文章，再手工对比、拼装和修正。他非常在意事实准确性，也担心技术错误。最痛的是：AI 对话里经常出现当时觉得很有用的判断，但几天后很难想起来它在哪里。

他的问题不是“没有 AI”，而是：

- AI 对话里的 useful point 容易丢失，几天后连"该搜什么"都忘了。
- 记性不好，很多已查过、已写过、已决定的内容容易丢失。
- 传统笔记 / 收藏夹 / 知识库都假设用户会主动整理、搜索、回看，但真实情况是不会。
- 市面上强自治 Agent 缺乏可控感，不值得完全信任。

## 目标用户

- 一人公司老板
- 高度重视事实准确性和表达质量
- 愿意使用 AI，但不愿失去过程控制权
- 需要系统长期记住自己的业务语境、写作偏好和研究轨迹，（comment：但是我发现过度限制AI，以及参考上下文，是写不出好文章的）

## 核心设计原则

### 1. Human in the loop

系统默认辅助，不默认代替用户做最终判断。

### 2. 证据优先

任何建议都尽量展示来源、时间、引用片段和可信度。

### 3. 记忆先于生成

第一版先解决“记住”和“找回”，再增强“生成”。

### 4. 机器做体力活，人做价值判断

机器负责连接、浮现、升温（体力活）；人负责"这条有没有用、要不要复用/沉淀"（价值判断）。不靠手动 promote，靠行为信号自动升温。

### 5. 语境驱动的二次浮现（核心差异点）

市面上"收藏 + 存库"工具很多，但几乎没人做"被动的、上下文相关的二次浮现"。这是本产品唯一别人没做、又最贴近初衷的命题：在对的时机把对的旧片段推回面前。

## MVP 范围

### 第一版优先输入源

- ChatGPT 对话里的 useful point（当前唯一真实入口）
- 其它入口（Claude / Gemini / 文档 / 网页）留待后续

### 第一版核心能力

- 低摩擦手动捕获（右键收藏，保住原文与来源）
- 机器连接：算相关、找重复（关键词起步，本地向量升级）
- 机器浮现：App 内 Review Queue，打开即浮出 3-5 条值得重看的旧片段 + 一句 why surfaced
- 人按需复用 / 忽略 / 沉淀；行为信号自动升温，不强制人工审核写入
- 按项目检索与回看

### 第一版暂不优先

- ChatGPT 页内实时语境提醒（Phase 2）
- 后台自治整理 agent
- 自动删除 / 合并 / 自动沉淀
- 复杂 UI、云同步、移动端
- 复杂多代理自治编排

## 核心用户故事

### 捕获

作为老板，当我在 ChatGPT 对话里看到一段有用的判断，我希望用一个极轻的动作（右键收藏）就把原文和来源保住，不打断我的思路，也不强迫我当场分类。

### 浮现（核心）

作为老板，我记性不好、也想不起"该搜什么"，所以我希望打开 review 页面时，系统主动浮出几条值得重看的旧片段，并告诉我为什么浮现，让旧想法回来找我，而不是等我去找它。

### 复用与沉淀

作为老板，当一条旧片段被浮现，我希望能一键复用、忽略一段时间或加入正式记忆；系统根据我的行为自动给它升温，而不是逼我手动整理。

## 成功指标

不是收藏数量，而是这些行为信号：

- 浮出来的旧片段有没有被点开 / 复用。
- 几天后仍然能通过项目库找回关键片段。
- 至少有几条旧片段因浮现被再次用于写作、决策或产品判断。
- 本地向量相比关键词，召回是否明显更好。
- 浮现频率不打扰（ADHD 敏感点）。
- 用户愿意持续打开 review 页面看回看面板。
