# Roadmap

## 2026-06-17 当前执行项目

当前执行项目收敛为 `ChatGPT Collect`。

这不是替换 `Solo Founder OS` 的长期愿景，而是把第一阶段原型入口缩小到一个足够清楚、能自己马上试用的场景：

`在 ChatGPT 网页选中 useful point -> 点击 Collect -> 保存到项目库 -> 后台整理 -> 后续重新浮现 -> 人工确认是否沉淀`

当前最重要的验证问题：

- 用户是否愿意在 ChatGPT 对话中频繁点击 `Collect`
- 这些 collected points 几天后是否真的能被找回
- 系统主动浮现旧片段时，是否能帮助用户复用旧判断
- 后台 agent 整理碎片是否降低了整理负担，而不是制造新的维护负担

当前实现顺序：

1. 修好现有本地 API 和 prototype 的持久化断裂
2. 新增 ChatGPT 网页选中收藏入口
3. 打通 `Collect -> 本地库 -> Review 页面`
4. 增加 `Useful Again` 和最小 `Review Queue`
5. 再加后台整理 agent：短标题、主题标签、相似片段候选

暂缓：

- 完整 `Founder OS`
- 通用网页剪藏器
- 多 agent 群聊
- 自动写作台
- 自动事实核验台
- 云同步和商业化包装

详细项目说明见 `docs/chatgpt-collect-project.md`。

## 阶段 0

目标：先把产品定义和边界收敛清楚。

交付物：

- 产品定位
- MVP 范围
- 信息架构
- 后续技术方案输入

## 阶段 1

目标：做出项目优先、记忆优先的最小可用版本。

范围：

- 建立 `Projects` 作为系统首页和上下文主边界
- 接入文档与笔记
- 接入写作历史
- 接入网页调研内容
- 自动生成候选记忆
- 建立 `Candidate Inbox`
- 建立 `Scratchpad` 作为临时层和快速星标入口
- 人工审核后写入 `Project Memory`
- 支持提升高价值内容到 `Global Consensus`
- 提供按项目过滤的基础检索和时间回放
- 默认不跨项目召回
- 打通最小的记忆来源追溯能力

验证问题：

- 用户是否真的更容易找回上下文
- 项目边界是否足够清晰，能否显著减少串台
- 用户是否愿意持续审核候选记忆
- 用户是否愿意主动使用星标或临时层保存重要内容
- 系统是否明显减少“忘事”和重复查找

## 阶段 2

目标：把记忆系统用于辅助写作。

范围：

- 关联历史草稿与相关资料
- 并排展示多路 LLM 输出
- 支持引用证据拼装最终稿
- 沉淀最终稿与改稿过程

验证问题：

- 是否显著减少跨文档复制粘贴
- 是否提高最终稿的一致性和可信度

## 阶段 3

目标：强化事实验证和最新资讯能力。

范围：

- 做出轻量 `Verification Desk` demo 并接入项目工作台
- 外部资料检索
- 新旧结论冲突提示
- 断言级核验
- 技术性风险提醒

验证问题：

- 用户是否更敢发布技术相关内容
- 错误信息是否更容易被提前发现

## 阶段 4

目标：进入客户沟通场景。

范围：

- 汇总客户上下文
- 提供沟通策略建议
- 生成回复草案
- 人工确认后再输出

验证问题：

- 是否减少遗漏和失误
- 是否提升沟通连贯性和跟进质量
